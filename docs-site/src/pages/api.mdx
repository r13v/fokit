# API

Use this page to find an exact public boundary. For the reasoning and complete
flows behind an API, follow the linked guide.

## Entry points

| Import | Use it for |
| --- | --- |
| `fokit` | React kits, native controls, generated forms, hooks, classic submit, and shared types |
| `fokit/core` | React-free stores, definitions, derived UI, paths, and immutable value helpers |
| `fokit/server` | Safe FormData normalization, Standard Schema validation, `FormResult`, and `SubmissionIssue` |
| `fokit/react19` | `ActionForm` and `ActionSubmit` |
| `fokit/layout.css` | Optional structural layout |

Start product forms from `fokit`. Import a narrower entry only where that
boundary belongs in the application.

## createFormKit

```text
createFormKit({ controls, slots? }) => FormKit
```

`controls` is required. `slots` is optional and partial; omitted slots resolve
from `createDefaultSlots()` when the kit is created.

```ts twoslash
import { createFormKit, nativeControls } from "fokit"

const kit = createFormKit({
	controls: nativeControls,
})
```

The returned kit exposes:

| Member | Purpose |
| --- | --- |
| `controls` | The exact typed control registry |
| `slots` | Resolved `Field`, `Section`, `Array`, `ArrayItem`, and `ErrorMessage` slots |
| `extend` | Create an add-only snapshot with local controls or slot replacements |
| `defineForm` | Normalize a schema and typed UI tree; its schema-bound function also exposes `fragment` |
| `AutoForm` | Create an instance and render the complete definition |
| `Form` | Render the native form shell for an existing instance |
| `Fields` | Render generated fields inside `kit.Form` |
| `Submit` | Submit button connected to disabled and pending state |

Read [Controls and design systems](/guides/controls) before replacing controls
or slots.

## kit.extend

```text
kit.extend({ controls?, slots? }) => FormKit
```

An extension snapshots the inherited registry and resolved slots. Controls are
add-only; a duplicate inherited name is a type error and a runtime error.
Slots are partial replacements. Provide at least one of `controls` or `slots`.

```ts twoslash
import { createFormKit, defineControl, nativeControls } from "fokit"

const baseKit = createFormKit({ controls: nativeControls })
const money = defineControl<number>({
	component: () => null,
	formData: {
		mode: "hidden",
		serialize(value, { name }) {
			return [{ name, value: String(value) }]
		},
	},
})

// ---cut---
const checkoutKit = baseKit.extend({
	controls: { money },
})
```

A base definition works with `checkoutKit`. A definition created through
`checkoutKit` retains its complete structural registry requirement and cannot
be rendered by `baseKit` or a sibling missing one of those names. Siblings with
the same complete registry contract are compatible.

For `Field`, `Section`, and `Array`, a replacement slot must accept the
inherited `slotOptions` type and may add optional properties. Presentation
compatibility follows the same base-to-extension direction through
`AutoForm`, manual `Form` composition, and `ActionForm`.

## kit.defineForm

```text
kit.defineForm(schema)({ ui }) => NormalizedFormDefinition
kit.defineForm(schema).withContext<Context>({ ui }) => NormalizedFormDefinition
```

The definition validates control names, typed paths, duplicate IDs, layout
ranges, and value policies. Passing the schema first lets TypeScript infer the
input type before it checks the UI tree. Use the direct object form for static
and derived UI. Resolver functions assigned to resolvable properties receive
schema-bound path autocomplete and inferred values. Paths read during the
resolver call are tracked automatically.
The normalized result is frozen and reusable across form instances.

```ts twoslash
import { createFormKit, nativeControls } from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })

// ---cut---
const definition = kit.defineForm(schema)({
	ui: [
		{
			kind: "field",
			path: "name",
			control: "text",
			label: "Name",
		},
	],
})
```

### Compose an object fragment

```text
const define = kit.defineForm(schema)
define.fragment(objectPath, nodes) => DefinitionFragmentNode[]
define.fragment.withContext<Context>()(objectPath, nodes)
```

Fragment field and array paths, plus resolver reads, are relative to the
selected object. The result is a schema-bound authoring value accepted directly
as `ui` or spread into the root `ui` array. Normalization erases the fragment
boundary and produces ordinary absolute nodes.

```ts twoslash
import { createFormKit, nativeControls } from "fokit"
import { z } from "zod"

const schema = z.object({
	profile: z.object({ first: z.string(), last: z.string() }),
})
const kit = createFormKit({ controls: nativeControls })
const define = kit.defineForm(schema)

// ---cut---
const profile = define.fragment("profile", [
	{ kind: "field", path: "first", control: "text", label: "First name" },
	{ kind: "field", path: "last", control: "text", label: "Last name" },
])

const definition = define.withContext<{ locale: string }>({ ui: profile })
```

Scopes must be definitely present, non-null, object-valued, and non-array.
Optional or nullable objects keep absolute nodes so missing-parent types are
preserved. Array item definitions continue to use the array node's relative
`children` contract. Explicit section and render IDs remain global across all
fragment scopes. Context-free fragments may be used in context-aware
definitions; bind `.withContext<Context>()` only when fragment resolvers require
that context.

### Render local React content

Use a render node for arbitrary form-local content that is not a field:

```tsx twoslash
// @jsx: react-jsx
import {
	createFormKit,
	nativeControls,
	type RenderNodeProps,
	useFormContext,
	useFormState,
} from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })

function NamePreview({ disabled, readOnly }: RenderNodeProps) {
	const form = useFormContext<typeof schema>()
	const name = useFormState(form, (snapshot) => snapshot.values.name)
	return <output aria-disabled={disabled || undefined}>{readOnly ? "Locked: " : ""}{name}</output>
}

// ---cut---
kit.defineForm(schema)({
	ui: [
		{
			kind: "render",
			id: "name-preview",
			component: NamePreview,
			visible: ({ name }) => name.length > 0,
		},
	],
})
```

Render nodes accept `visible`, `disabled`, and `readOnly`. An invisible node is
unmounted; a mounted component receives effective `disabled` and `readOnly`
props after parent and form state are inherited. It may use public hooks for
values. Fokit provides no field, layout, accessibility, command ownership, or
FormData behavior for its contents, so the component must honor the flags in
its arbitrary DOM. Render nodes work at the root and inside sections, but not
inside array rows.

### UI resolvers

```text
property: (values, { context }) => result
```

`values` is a readonly map of canonical form paths to their typed values.
Destructuring reads and tracks only the named paths:

```ts twoslash
import { createFormKit, nativeControls } from "fokit"
import { z } from "zod"

const schema = z.object({
	accountType: z.enum(["personal", "company"]),
	address: z.object({ country: z.string() }),
})
const kit = createFormKit({ controls: nativeControls })

// ---cut---
kit.defineForm(schema)({
	ui: [
		{
			kind: "field",
			path: "accountType",
			control: "select",
			options: {
				options: [
					{ value: "personal", label: "Personal" },
					{ value: "company", label: "Company" },
				],
			},
			visible: ({ accountType }) => accountType === "company",
		},
		{
			kind: "field",
			path: "address.country",
			control: "text",
			visible: ({ "address.country": country }) => country === "GB",
		},
	],
})
```

The cached result is reused until a tracked value or the `context` reference
changes. The values proxy exists only for the synchronous resolver call. Rest
destructuring, spread, and enumeration are rejected; remote data should be
loaded outside the resolver and passed through `context`.

A function assigned directly to a resolvable property is always a resolver.
When custom control options contain callbacks, keep those callbacks inside an
options object rather than using a function as the complete `options` value.

### UI node families

The `ui` array is a typed tree:

| `kind` | Data path | Purpose |
| --- | --- | --- |
| `"field"` | required | Connect one typed value to one registered control |
| `"section"` | none | Group nodes and provide a responsive grid |
| `"array"` | required | Repeat relative child nodes for every array item |
| `"render"` | none | Mount form-local React content with no field contract |

All four node kinds accept `visible`, `disabled`, and `readOnly` as
either booleans or resolver functions. Those states inherit through sections
and arrays. They also accept static `className` and `span`; the shipped layout
uses `span` for direct children of a section grid. Render nodes additionally
require `id` and `component` and receive the resolved interaction props.

`disabled` makes a node unavailable. `readOnly` keeps its controls enabled and
focusable but prevents changes. See [UI definitions: Choose disabled or
read-only](/guides/ui-definitions#choose-disabled-or-read-only) for form-wide
submission behavior and when to use each state.

#### Field node

| Property | Required | Type or default |
| --- | --- | --- |
| `path` | yes | Typed `FieldPath<FormInput<Schema>>` |
| `control` | yes | A compatible key from this kit's control registry |
| `id` | no | Derived from `path` |
| `label`, `description` | no | `ReactUiContent` or a resolver function |
| `slotOptions` | no | Options inferred from the registered `Field` slot, or a resolver function |
| `required` | no | `boolean` or a resolver function; default `false` |
| `visible` | no | `boolean` or a resolver function; default `true` |
| `disabled`, `readOnly` | no | `boolean` or a resolver function; default `false` |
| `valuePolicy` | no | `"preserve"` or `"unset"`; default `"preserve"` |
| `options` | no | Options inferred from `control`, or a resolver function |
| `className`, `span` | no | Static styling and grid metadata |

`required` configures presentation, native state, and ARIA; validation still
belongs to the Standard Schema. `"unset"` is available only for paths that can
be absent or contain `undefined`.

#### Section node

| Property | Required | Type or default |
| --- | --- | --- |
| `id` | yes | Unique non-empty string without ASCII whitespace |
| `children` | yes | Nested `field`, `section`, `array`, or `render` nodes |
| `title`, `description` | no | `ReactUiContent` or a resolver function |
| `slotOptions` | no | Options inferred from the registered `Section` slot, or a resolver function |
| `columns` | no | `1`, `2`, `3`, or `4`; default `1` |
| `visible` | no | `boolean` or a resolver function; default `true` |
| `disabled`, `readOnly` | no | `boolean` or a resolver function; default `false` |
| `className`, `span` | no | Static styling and grid metadata |

Inside a section, fields default to `span: 1`; nested sections and arrays
default to `span: "full"`.

#### Array node

| Property | Required | Type or default |
| --- | --- | --- |
| `path` | yes | Typed `ArrayFieldPath<FormInput<Schema>>` |
| `itemDefault` | yes | A complete item or a function returning one |
| `children` | yes | UI nodes with paths relative to one item |
| `id` | no | Derived from `path` |
| `label`, `description` | no | `ReactUiContent` or a resolver function |
| `slotOptions` | no | Options inferred from the registered `Array` slot, or a resolver function |
| `visible` | no | `boolean` or a resolver function; default `true` |
| `disabled`, `readOnly` | no | `boolean` or a resolver function; default `false` |
| `className`, `span` | no | Static styling and grid metadata |

Definitions reject unknown controls, duplicate paths within one scope,
duplicate node IDs, invalid layout ranges, and unsupported value policies.
Read [UI definitions](/guides/ui-definitions) for inheritance, hidden-value
behavior, arrays, layout, and manual-composition boundaries.

`ReactUiContent` is `string | ReactElement`. The React-free core defaults these
properties to strings and treats presentation values and structural slot
options as opaque payloads.

## AutoForm

`kit.AutoForm` accepts native form props plus:

| Prop | Required | Purpose |
| --- | --- | --- |
| `definition` | yes | Normalized definition from this kit |
| `defaultValues` | yes | Complete editable `FormInput` baseline |
| `context` | no | Runtime-only data for UI resolvers |
| `validation` | no | Partial validation options |
| `disabled` | no | Make the complete form unavailable and prevent submission |
| `readOnly` | no | Prevent edits while keeping the form available for submission |
| `beforeUpdate`, `afterUpdate` | no | Transaction hooks |
| `onSubmit` | no | Validated callback that returns `void` or `Promise<void>` |

Validation defaults are `mode: "submit"`, `revalidateMode: "change"`, and
`asyncDebounceMs: 0`.

The submit callback receives `{ value, input, form, formData }`. `value` is
validated `FormOutput`; `input` is the captured editable shape.

If `onSubmit` returns a promise, Fokit waits for it. `isSubmitting` remains
`true`, and `kit.Submit` remains disabled until the promise settles. Concurrent
submit attempts use the same in-flight promise and do not call `onSubmit`
again.

Fokit does not reset the form after success. Call `form.reset(...)` explicitly
when saved values must become the new baseline. Fokit does not convert a thrown
error or rejected promise into a form issue. Handle expected failures in the
callback and use `form.setErrors(...)` for user-visible issues.

## useForm

```text
useForm(definition, options) => FormInstance
useForm(form, runtimeOptions) => same FormInstance
```

The definition overload creates one stable instance. The instance overload
returns the supplied object. Runtime options update without replacing either
instance; changing `defaultValues` does not overwrite edits.

```tsx twoslash
// @jsx: react-jsx
import { createFormKit, nativeControls, useForm } from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })
const definition = kit.defineForm(schema)({
	ui: [
		{
			kind: "field",
			path: "name",
			control: "text",
			label: "Name",
		},
	],
})

// ---cut---
function ProfileForm() {
	const form = useForm(definition, {
		defaultValues: { name: "" },
		onSubmit({ value }) {
			value.name.toUpperCase()
		},
	})

	return (
		<kit.Form form={form}>
			<kit.Fields />
			<kit.Submit>Save</kit.Submit>
		</kit.Form>
	)
}
```

Use `createForm` when the instance must exist outside a React component:

```tsx twoslash
// @jsx: react-jsx
import { createForm, createFormKit, nativeControls, useForm } from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })
const definition = kit.defineForm(schema)({
	ui: [{ kind: "field", path: "name", control: "text" }],
})
const profileForm = createForm(definition, {
	defaultValues: { name: "" },
})

// ---cut---
function ProfileForm({ disabled }: { readonly disabled: boolean }) {
	const form = useForm(profileForm, {
		disabled,
		onSubmit({ value }) {
			value.name.toUpperCase()
		},
	})

	return (
		<kit.Form form={form}>
			<kit.Fields />
			<kit.Submit>Save</kit.Submit>
		</kit.Form>
	)
}
```

The external instance owns its definition, baseline, and fallback runtime
configuration. While mounted, `useForm(form, runtimeOptions)` applies the
latest committed React options. Unmount restores the external configuration.
One instance may have only one active `useForm` binding. Create external
instances per request rather than as server process singletons.

Use `form.reset(loadedValues)` when loaded or saved data should become the new
clean baseline.

## Hooks

Hooks subscribe only to the selected slice:

| Hook | Returns |
| --- | --- |
| `useValue(form, path)` | The typed value at one path |
| `useField(form, path)` | Value, setter, blur, focus, ref, and visible field metadata |
| `useArrayField(form, path)` | Stable row keys, array metadata, and typed array commands |
| `useFormState(form, selector, options?)` | A selected snapshot value with optional equality |
| `useFormContext()` | The nearest instance inside `kit.Form` or `FormProvider` |

See [Arrays](/guides/arrays) for generated and manual array controls.

## FormInstance

The instance is an external store plus typed commands.

### Values and transactions

| Method | Purpose |
| --- | --- |
| `getValues()`, `getValue(path)` | Read current input without subscribing |
| `setValue(path, value)` | Set one typed field path |
| `setValues(partial)` | Apply a deep partial input update |
| `unsetValue(path)` | Remove an optional field |
| `batch(callback)` | Commit several commands as one transaction |
| `reset(values?)` | Restore or replace the baseline |

These value commands accept every typed canonical schema path, even when no UI
field is registered for it. Generated rendering, field metadata, and
`ActionForm` serialization still require actual nodes and controls. Array
structure commands require an array node because they use `itemDefault` and
stable row metadata.

`beforeUpdate` and `afterUpdate` receive path/value-correlated
`ValueChange<FormInput<Schema>>` entries. `extendValueChanges(event, additions)`
returns the incoming transaction plus typed additions, or `undefined` when the
addition list is empty.

Read [Transaction hooks](/guides/transaction-hooks) for the lifecycle, return
values, update sources, and complete examples.

### Arrays

`append`, `insert`, `remove`, and `move` update values, row keys, metadata, and
issues atomically.

### Validation and errors

| Method | Purpose |
| --- | --- |
| `validate()` | Validate the form and return transformed output or issues |
| `validate(path)` | Validate the complete schema and return overlapping issues for one path |
| `validatePaths(paths)` | Validate once and return overlapping issues for one or more typed paths |
| `focusFirstError(paths?)` | Focus the first displayed editable field or mounted summary in an optional subset; return whether focus moved |
| `setErrors(issues)` | Install and expose manual or server issues |
| `clearErrors(path?)` | Clear imperative issues globally or under a path |
| `blur(path)`, `touch(path)`, `focus(path)` | Manage interaction and focus |

### Submission and observation

| Method | Purpose |
| --- | --- |
| `submit()` | Request classic submission and return its in-flight promise |
| `getSnapshot()` | Read immutable form state |
| `subscribe(selector, listener, options?)` | Observe selected state outside React |
| `replaceContext(context)` | Recompute context-dependent UI |
| `replaceOptions(options)` | Fully replace runtime behavior while preserving context |

`replaceOptions` replaces `disabled`, `readOnly`, validation settings, and
update/submit callbacks. Omitted options return to their defaults. A later
committed `useForm(form, runtimeOptions)` update remains authoritative while
the instance is React-bound.

`form.submit()` uses the same lifecycle as a native submit. It resolves without
calling `onSubmit` when the form is disabled or invalid. It rejects if
`onSubmit` throws or returns a rejected promise.

Read [Validation and errors](/guides/validation) for visibility and stale-result
rules.

## defineControl

```text
defineControl({ component, formData }) => ControlDefinition
```

The component receives typed `ControlProps`: value, `setValue`, `blur`, native
input wiring, metadata, options, context, and interaction state.

`formData.mode` is `"native"`, `"hidden"`, or `"none"`. A serializer returns
the entries used when Fokit must represent the value outside a visible native
control.

`nativeControls` contains `text`, `textarea`, `select`, `checkbox`, `number`,
`date`, `time`, and single-file `file`.

### nativeControls

The shipped registry uses native HTML controls and preserves their value,
accessibility, read-only, and `FormData` behavior:

| Control | Store value | `options` |
| --- | --- | --- |
| `text` | `string \| undefined` | `type?: NativeTextType`, `placeholder?: string`, `autoComplete?: string` |
| `textarea` | `string \| undefined` | `placeholder?: string`, `autoComplete?: string`, `rows?: number` |
| `select` | `string \| undefined` | `emptyOption?: { label: string; disabled?: boolean }`, `options: readonly { value: string; label: string; disabled?: boolean }[]` |
| `checkbox` | `boolean` | none |
| `number` | `number \| undefined` | `min?: number`, `max?: number`, `step?: number \| "any"`, `placeholder?: string` |
| `date` | `string \| undefined` | `min?: string`, `max?: string` |
| `time` | `string \| undefined` | `min?: string`, `max?: string`, `step?: number \| "any"` |
| `file` | `File \| undefined` | `accept?: string`; one file |

#### Text

`NativeTextType` accepts `"text"`, `"email"`, `"password"`, `"search"`,
`"tel"`, or `"url"`.

If you omit `type`, the control uses `"text"`.

#### Select

`select.options` is required.

Define `select.emptyOption` when the current value can be `undefined`. It adds a
separate option with `value=""`. Fokit maps this option to `undefined`.

Without `emptyOption`, a normal option with `value=""` remains an empty string.

The visible native element always submits `""` for an empty option. Server
schemas must normalize `""` when they validate optional enums.

#### Time

A numeric `time.step` specifies a duration in seconds. This behavior matches the
native input contract.

#### Exported option types

The package exports these option types:

- `NativeTextOptions`
- `NativeTextareaOptions`
- `NativeSelectOptions`
- `NativeSelectOption`
- `NativeSelectEmptyOption`
- `NativeNumberOptions`
- `NativeDateOptions`
- `NativeTimeOptions`
- `NativeFileOptions`

A field can derive its `options` from tracked form values or runtime context.

See [Controls and design systems](/guides/controls) for adapter and serializer
contracts.

## createDefaultSlots

```text
createDefaultSlots({ i18n? }) => FormKitSlots
```

The returned slots render accessible unstyled structure. Array rows show
compact `↑`, `↓`, and `❌` actions while keeping their localized labels for
screen readers and tooltips. I18n values can be strings or functions receiving
the row position and label context.

## parseFormData

```text
parseFormData(formData, schema, options?) => Promise<ParseResult<Output>>
```

The parser reconstructs nested values and arrays, rejects unsafe structures,
then validates with Standard Schema.

```ts twoslash
import { parseFormData } from "fokit/server"
import { z } from "zod"

const schema = z.object({ name: z.string().min(1) })
const formData = new FormData()
formData.set("name", "Ada")

// ---cut---
const result = await parseFormData(formData, schema)

if (result.success) {
	result.value.name
} else {
	result.reply()
}
```

Options limit entry count, path length, nesting depth, and array index size.
Framework-level request and file limits still run first.

## React 19

`ActionForm` renders a normalized definition into a native React 19 Action
form. `ActionSubmit` follows React pending status and Fokit submission state.
Both come from `fokit/react19`.

See the end-to-end [React 19 Actions guide](/guides/react-19-actions).

## React-free core

Use `fokit/core` in shared packages, non-React runtimes, and focused tests.

- `createFormStore` creates the immutable external store.
- Resolver functions in definitions derive UI with tracked value reads.
- `normalizeDefinition` and `resolveUi` normalize and resolve those definitions.
- `parsePath`, `formatPath`, `parseArrayIndex`, `isSamePath`,
  `isAncestorPath`, `isDescendantPath`, and `pathsOverlap` work with canonical
  paths.
- `getPathValue`, `setPathValue`, `unsetPathValue`, `mergePathValue`,
  `cloneValue`, and `isDirtyEqual` handle supported values immutably.

Type contracts are grouped in the [TypeScript reference](/types).
