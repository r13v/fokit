# React 19 Actions

React 19 Actions are a separate, server-first submission mode. The same schema,
definition, controls, and field errors remain useful, but the server owns
parsing and validation.

## Choose the submission owner

| Use classic `onSubmit` when… | Use `ActionForm` when… |
| --- | --- |
| client validation should run before dispatch; | a React 19 Action owns the request; |
| a client callback owns persistence or mutation; | the server must parse native `FormData`; |
| React 18 compatibility is required. | pending state and returned errors follow Action state. |

`ActionForm` does **not** run client validation before dispatch. The Action must
validate every submission on the server.

Classic forms work in React 18 and 19 from the main `fokit` entry. Action-only
components live in `fokit/react19`, so React 18 consumers never load their
declarations.

## Connect the client form

Keep `createFormKit`, controls, and definitions in the main entry. Import only
the Action boundary from `fokit/react19`:

```tsx twoslash
// @jsx: react-jsx
import { createFormKit, nativeControls } from "fokit"
import { ActionForm, ActionSubmit } from "fokit/react19"
import type { FormResult } from "fokit/server"
import { useActionState } from "react"
import { z } from "zod"

const schema = z.object({
	name: z.string().min(1, "Name is required"),
})
const kit = createFormKit({ controls: nativeControls })
const definition = kit.defineForm(schema)({
	ui: [
		{
			kind: "field",
			path: "name",
			control: "text",
			label: "Name",
		},
	],
})
const defaultValues = { name: "" }

type SaveProfile = (
	previousResult: FormResult | undefined,
	formData: FormData,
) => Promise<FormResult>

// ---cut---
function ProfileActionForm({
	saveProfile,
}: {
	readonly saveProfile: SaveProfile
}) {
	const [result, action] = useActionState(saveProfile, undefined)

	return (
		<ActionForm
			action={action}
			defaultValues={defaultValues}
			definition={definition}
			kit={kit}
			result={result}
		>
			<ActionSubmit>Save profile</ActionSubmit>
		</ActionForm>
	)
}
```

`ActionForm` keeps the supplied Action on the native form, renders the same
definition as `AutoForm`, emits hidden serializer inputs when needed, and
applies the returned `FormResult` after hydration.

`ActionSubmit` is an unstyled native button. It combines React Action pending
status with Fokit's disabled and submitting state.

Use `parseFormData` from `fokit/server`. It reconstructs repeated and nested
values, rejects unsafe structures, then runs Standard Schema validation:

```ts
// [!include ~/snippets/server-action.ts]
```

Do not decode a Fokit submission with `Object.fromEntries`. Repeated values and
`__fokit.array` markers carry array structure. Browser controls also retain
protocol values such as number strings, date strings, absent unchecked
checkboxes, and `File` objects.

Framework request limits, multipart parsing, file count, and file size checks
still run before `parseFormData`.

## Return serializable results

The Action returns one small transport:

```ts twoslash
import type { SubmissionIssue } from "fokit/server"

// ---cut---
type FormResult =
	| { status: "success"; reset?: "defaults" | "submitted" }
	| { status: "error"; issues: readonly SubmissionIssue[] }
```

Field issues use canonical dotted paths. Omit `path` for a form-level error.
On success:

- omit `reset` to keep current values;
- use `"defaults"` to restore the original baseline;
- use `"submitted"` to make the submitted server result the new baseline.

User edits made while an Action is in flight are not overwritten by a stale
result.

## Know the compatibility boundary

`ActionForm` stops before dispatch when active values cannot be represented in
native FormData:

- a control uses `mode: "none"`;
- a hidden or disabled native control has no serializer;
- a hidden or disabled file field would need hidden preservation;
- the current runtime does not expose React 19 Action support.

Use [Controls and design systems](/guides/controls) to choose the right
serialization mode. Use [Validation and errors](/guides/validation) for the
classic client-owned lifecycle.
