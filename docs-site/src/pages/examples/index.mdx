# Complex form examples

These examples are deliberately larger than a feature sampler. Each one owns a
coherent product workflow, uses a complete Standard Schema, and sends typed
output through deterministic fake requests in TanStack Query. No remote server
or private application code is required.

## Choose a stress case

- [Research grant application](/examples/research-grant) — conditional
  applicant identity, an asynchronous registry, cascade cleanup, live preview,
  and two-step submission.
- [Creative studio policies](/examples/studio-policies) — two loaded resources,
  cross-section rules, nested policy groups, a movable equipment array, and two
  writes.
- [Makerspace launch wizard](/examples/makerspace-launch) — four form-owned
  stages, address resolution, coordinates, files, gallery rows, capacity
  pricing, four promotions, and three writes.
- [Learning cohort editor](/examples/learning-cohort) — asynchronous title
  suggestions, session and pricing matrices, media, four offer subforms, and
  save-conflict recovery.
- [Membership ladder](/examples/membership-ladder) — four cascading tiers,
  nested benefit arrays, workspace connection, and calendar-assisted pauses.
- [Campaign builder](/examples/campaign-builder) — seven payload variants that
  share audience, schedule, channel, payment, and create-or-edit behavior.

## What to look for

Change a discriminator and watch inactive values leave the form transaction.
Reorder array rows and confirm their state moves with them. Trigger a fake
request and keep editing while request state remains outside Fokit. The examples
are designed to make ownership visible: Fokit owns editable values and form
semantics; TanStack Query owns remote lifecycle and cache state.
