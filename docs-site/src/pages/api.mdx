# API

This page lists the public runtime APIs and the types that control their
behavior. Import each optional feature from its own package entry.

## Entry points

| Import | Public capability |
| --- | --- |
| `form-please` | Form kits, React components, hooks, commands, transactions, events, and shared types |
| `form-please/core` | React-free `createFormStore` plus core types and helpers |
| `form-please/default-slots` | Accessible structural slot factory and localization types |
| `form-please/history` | History, journals, cursors, and pure replay |
| `form-please/native-controls` | Native HTML control factory and option types |
| `form-please/persistence` | Persistence, adapters, codecs, and migration |
| `form-please/preset-native` | Ready-to-use native controls and accessible default slots |
| `form-please/devtools` | Constrained Redux DevTools integration |
| `form-please/react19` | `ActionForm` and `ActionSubmit` |
| `form-please/server` | `parseFormData` and server result types |

The main entry does not export global `createForm`, `useCreateForm`,
`useBindForm`, `useForm`, or `createFormStore`. It also does not export
`KitForm`, a root `Submit` value, `UseFormOptions`, rendering defaults, or
optional feature code.

## createFormKit

```ts
// [!include ~/snippets/api-reference.tsx:create-form-kit]
```

The function freezes one controls-and-slots snapshot. `kit.extend` creates a
new snapshot. A form belongs to the exact snapshot that created it.

```tsx twoslash
import { createFormKit } from "form-please"
import { createDefaultSlots } from "form-please/default-slots"
import { createNativeControls } from "form-please/native-controls"

const kit = createFormKit({
	controls: createNativeControls(),
	slots: createDefaultSlots(),
})
```

Control names are add-only. An extension can replace compatible slots, but it
cannot replace an inherited control. Base, extended, and sibling kits are
different owners.

## nativeFormKit

Import `nativeFormKit` from `form-please/preset-native` when the shipped
native controls and accessible English default slots are the desired baseline:

```tsx twoslash
import { nativeFormKit as kit } from "form-please/preset-native"
```

The preset is a frozen `FormKit`. Extend it to add application controls or
replace compatible slots. Use `createFormKit`, `createNativeControls`, and
`createDefaultSlots` directly when localization or complete registry
construction must be explicit.

## kit.forContext

`kit.forContext<Context>()` binds one context contract to the complete kit API.
It is a type-only view: it returns the same frozen kit object and keeps the same
controls, slots, descriptor, and ownership identity. `kit.extend(...)` preserves
the bound context.

Use that contextual view to define forms, create instances, and bind them to
React. A concrete context is required at every creation and binding boundary.
Runtime context may add fields to the authoring contract; those richer fields
remain available through the resulting `FormInstance`.

```ts

```

## Form and AutoForm

```tsx
// [!include ~/snippets/api-reference.tsx:form-components]
```

`kit.Form` renders native form behavior and its children. It accepts native
form props and `form`. Call `kit.useBindForm(form, runtimeOptions)` separately
when a manual form needs a runtime binding. `kit.AutoForm` accepts native form
props and `FormRuntimeOptions`, and it renders the error summary and definition
fields. Both components reject a form from another exact kit.

Use `kit.Fields` inside `kit.Form` for manual composition. Use `kit.Submit` for
the kit-owned submit button. Register `slots.Submit` to replace its markup. The
slot receives `buttonProps`, the immutable current input `values`, and
`isSubmitting`. Forward `buttonProps` to the actual submit control so the
owned `type="submit"`, disabled state, children, and native props remain intact.

## Hooks

| API | Result |
| --- | --- |
| `useFormContext()` | The nearest `FormInstance` from `FormProvider` or a form component |
| `useFormState(form, selector, options?)` | A selected snapshot value |
| `useSnapshot(handle)` | The current snapshot from a history or persistence handle |
| `useValue(form, path, options?)` | The typed value at a path |
| `useField(form, path)` | Value, issues, metadata, and field commands |
| `useArrayField(form, path)` | Stable rows and typed array commands |

`FormProvider` and `useFormContext` remain public for headless composition.
Get a history or persistence handle with `feature.handle(form)`. Use
`useSnapshot(handle)` to subscribe a React component to that handle. Use
`useFormState` for a form, and subscribe to the smallest state slice that the
component needs.

## FormInstance

The instance is the primary command API:

```ts
// [!include ~/snippets/api-reference.tsx:form-instance]
```

Mutation commands return `void`. `validate()` returns a schema validation
result. Path validation returns overlapping issues. `focusFirstError` returns
whether focus moved. `reset(values)` installs a new clean document. `reset()`
restores the current clean baseline. Use `clearErrors()` for every imperative
issue or `clearErrors(path)` for one path.

### Classic submission

`onSubmit` can return `void` or `Promise<void>`. The form keeps
`isSubmitting` true until the promise settles, and concurrent submissions use
the same in-flight promise. A rejected promise does not become a form issue.
Catch expected request failures. Call `form.setErrors(...)` when the user needs
feedback. Call `form.reset(...)` after a save when the saved values must become
the clean baseline. `form.submit()` uses the same lifecycle as a native classic
submit.

## Transactions

`FormTransaction<Input, Context>` is the immutable transaction union handled
by middleware:

```ts
// [!include ~/snippets/api-reference.tsx:transactions]
```

`DocumentTransaction` has `type: "document/committed"`, a source, grouping,
value changes, row-identity changes, and baseline disposition.
`RestoreTransaction` has `type: "document/restored"`, a complete document,
an origin, and history policy. Runtime transactions describe context,
validation, submission, touch, blur, issue, and reset transitions.

Transactions are immutable. A middleware handler can forward one unchanged,
forward a replacement, or cancel it.

## Events

`FormEvent<Input, Context>` is the committed event union:

- `document/committed` and `document/restored`;
- `runtime/replaced` and `runtime/reset`;
- `validation/started`, `validation/resolved`, and `validation/failed`;
- `submission/started` and `submission/finished`;
- `field/touched` and `field/blurred`;
- `issues/changed`.

Each event has a monotonic `sequence`. Document events are replayable.
Runtime events are not stored in history or persistence.

The phase is `"idle"`, `"restoring"`, `"active"`, or `"conflict"`. Save state
is `"idle"`, `"scheduled"`, `"saving"`, or `"failed"` with an error.
Restore returns `"applied"`, `"empty"`, `"cancelled"`, `"transformed"`,

Construction is idle. Call `restore()` before local edits. A successful or
empty restore activates saving. Call `start()` when the application skips or
recovers from restore. A local edit during asynchronous restore produces a
conflict and remains authoritative.

## Redux DevTools

Create the optional integration with `createDevToolsMiddleware`:

```ts
// [!include ~/snippets/api-reference.tsx:devtools]
```

The feature connects only after the form completes its first retained React
binding through `kit.useBindForm`, `kit.AutoForm`, or `ActionForm`. A form that is
never bound does not open a DevTools listener. For manual `kit.Form`
composition, call `kit.useBindForm(form, runtimeOptions)` in the component.

```ts
// [!include ~/snippets/api-reference.tsx:devtools-options]
```

Supported connection options are `name`, `latency`, `maxAge`, `trace`,
`traceLimit`, `serialize`, `actionSanitizer`, `stateSanitizer`,
`actionsAllowlist`, `actionsDenylist`, `predicate`, and `autoPause`.
`onError` receives integration failures. `maxAge` defaults to `50` and must be
an integer greater than `1`. `autoPause` defaults to `true`.

The integration sends committed events and a diagnostic projection of values
and logical row identity. It supports `JUMP_TO_STATE`, `JUMP_TO_ACTION`,
`RESET`, `ROLLBACK`, and `COMMIT`. `COMMIT` changes only the monitor baseline.
The integration rejects arbitrary dispatch, skip, reorder, import, lock,
persisted monitor state, and generated tests. Navigation uses only an opaque
revision token from the bounded local table. The integration adds this token
after `stateSanitizer` runs, so a sanitizer cannot replace it. Sanitized or
serialized monitor state is never trusted as form input.

`disconnect()` is idempotent, permanent for that form, and affects only that
form. It removes the extension listener and the form event listener. The
feature is inert during SSR or when the extension is absent. See
[Redux DevTools](/guides/devtools).

## parseFormData

```ts twoslash
import { parseFormData } from "form-please/server"
import { z } from "zod"

const schema = z.object({ name: z.string().min(1) })
const formData = new FormData()
formData.set("name", "Ada")

const result = await parseFormData(formData, schema)

if (result.success) {
	result.value.name
} else {
	result.reply()
}
```

The parser normalizes bounded untrusted `FormData` and runs Standard Schema.
Defaults are `maxEntries: 1_000`, `maxPathLength: 1_024`, `maxDepth: 32`, and
`maxArrayIndex: 10_000`. Apply request and file limits before this function.
