# Build a production form

This tutorial continues the form from [Get started](/get-started). You will keep
one schema, one UI definition, and one kit while adding the behavior that makes
a form survive real product work:

- validation that stays quiet until it is useful;
- a company field that appears only when relevant;
- repeatable contacts with stable row identity;
- transformed, typed output at submit.

The finished form still uses the shipped native controls. Connecting your
design system is a separate rendering decision, not a rewrite of form state.

## Model editable input and saved output

The schema owns validity and transformations. `FormInput` is the shape edited
by controls; `FormOutput` is the shape delivered after successful validation.

```tsx
// [!include ~/snippets/form-kit.tsx:schema]
```

The editable input has no `contactCount`. The validated output does. Fokit
keeps those types separate through definitions, hooks, and submit callbacks.

Cross-field validation also stays in the schema. The company rule therefore
works in client validation and in server parsing without duplicating business
logic in a component.

## Describe the product UI

The definition maps typed schema paths to controls. It also makes two product

- `companyName` depends on `accountType` and is removed when hidden;

The schema-bound resolver function infers every value it reads. Fokit tracks
those paths automatically and reuses the result until a tracked value changes.
The resolver is synchronous and pure.
`valuePolicy: "unset"` is allowed because `companyName` is optional in
editable input.

The array node does not add hidden IDs to your values. Fokit keeps stable row
keys as UI metadata while paths, touched state, and visible issues move with
the logical row.

Try these paths in the form:

1. Clear the name and blur it. The field shows its schema issue.
2. Choose Company. The company field appears.
3. Switch back to Personal. `companyName` leaves the stored input.
4. Add, reorder, or remove a contact. Its row state stays attached correctly.
5. Submit. The callback receives transformed output with `contactCount`.

## Know what is already handled

This form now has:

- complete typed defaults and deterministic reset;
- native labels, names, FormData, and submit semantics;
- submit-time focus for the first visible invalid field;
- blur-first validation and change revalidation;
- stable array commands and accessible default action labels;
- a clear boundary for custom controls and structural slots.

Success does not reset automatically. After persisting the value, choose the
baseline your product needs:

```ts twoslash
import type { FormInstance } from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
declare const form: FormInstance<typeof schema>
declare const saved: { readonly name: string }

// ---cut---
form.reset(saved)
```

`reset(saved)` replaces both current values and the dirty-comparison baseline,
which is the usual edit-form behavior after a successful save.
