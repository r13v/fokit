# Shadcn with Valibot

This example keeps the design-system boundary in your application. The registry
item copies a small adapter next to your existing shadcn components; Form,
Please stays headless and Valibot supplies the Standard Schema.

## Install the adapter

The first Form, Please release containing this item is `v1.1.0`:

```bash
npx shadcn@latest add r13v/form-please/shadcn-form-kit#v1.1.0
```

The item targets shadcn's **Base UI** implementation. Because the adapter is
application-owned, review its imports after installation if your local shadcn
components were generated with another style or customized props. The copied
source lives at `components/ui/form-please/shadcn-form-kit.tsx` by default.

## Try the workshop proposal

Change a radio or switch, move all three slider shapes, search the comboboxes,
choose calendar values, and edit the OTP. Submit to run the Valibot schema.

<ShadcnValibotWorkshopDemo />

## What the adapter includes

- Native-shaped `text`, `textarea`, `select`, `checkbox`, `number`, `date`,
  `time`, and `file` controls.
- Base UI `radio`, `switch`, `combobox`, and `multiCombobox` controls.
- `slider`, fixed two-thumb `rangeSlider`, and arbitrary-thumb `multiSlider`.
- ISO-string `datePicker`, `{ from, to }` `dateRangePicker`, and `inputOtp`.
- Form, Please slots built from local shadcn Field and Button primitives.

The adapter remains normal source code in your repository, so it can follow
your aliases, styling, and component signatures without becoming a second
component library.
