# API

This page lists the public runtime APIs and the types that control their
behavior. Import each optional feature from its own package entry.

## Entry points

| Import | Public capability |
| --- | --- |
| `form-please` | Form kits, React components, hooks, commands, transactions, events, and shared types |
| `form-please/core` | React-free `createFormStore` plus core types and helpers |
| `form-please/history` | History, journals, cursors, and pure replay |
| `form-please/persistence` | Persistence, adapters, codecs, and migration |
| `form-please/devtools` | Constrained Redux DevTools integration |
| `form-please/react19` | `ActionForm` and `ActionSubmit` |
| `form-please/server` | `parseFormData` and server result types |

The main entry does not export global `createForm`, global `useForm`, or
`createFormStore`. It also does not export `KitForm`, a root `Submit` value,
`UseFormOptions`, or optional feature code.

Every configured first-party feature uses `feature.handle(form)` to return its
stable per-form handle.

## createFormKit

```text
createFormKit({ controls, slots? }) => FormKit
```

The function freezes one controls-and-slots snapshot. `kit.extend` creates a
new snapshot. A form belongs to the exact snapshot that created it.

```text
import { createFormKit, nativeControls } from "form-please"

const kit = createFormKit({ controls: nativeControls })
```

Control names are add-only. An extension can replace compatible slots, but it
cannot replace an inherited control. Base, extended, and sibling kits are
different owners.

## kit.defineForm

```text
kit.defineForm(schema)({ ui }) => NormalizedFormDefinition
kit.defineForm(schema).withContext<Context>()({ ui })
kit.defineForm(schema).fragment(scope, nodes)
```

Normalization checks paths, IDs, controls, slots, and array defaults. Resolver
functions are synchronous. They can read values and runtime context.

Nodes use `kind: "field"`, `"section"`, `"array"`, or `"render"`. Field
options include `visible`, `disabled`, `readOnly`, and `valuePolicy`. An array
requires `itemDefault` when append or insert needs a default item.

## CreateFormOptions

```text
type CreateFormOptions<Schema, Context = unknown> = {
	defaultValues: FormInput<Schema>
	context?: Context
	disabled?: boolean
	readOnly?: boolean
	validation?: Partial<ValidationOptions>
	beforeUpdate?: (event: BeforeUpdateEvent) => false | readonly ValueChange[] | undefined
	afterUpdate?: (event: UpdateEvent) => void
	onSubmit?: SubmitHandler<Schema, Context>
	middleware?: readonly FormMiddleware[]
}
```

`defaultValues` is required. The middleware array is copied and frozen at form
creation. Duplicate middleware references, invalid first-party cardinality,
and missing feature dependencies make form creation fail atomically.

Validation defaults are `mode: "submit"`, `revalidateMode: "change"`, and
`asyncDebounceMs: 0`.

## kit.createForm

```text
kit.createForm(definition, options: CreateFormOptions) => FormInstance
```

Use lazy React state for a component-local form:

```text
import { useState } from "react"

function Editor() {
	const [form] = useState(() =>
		kit.createForm(definition, { defaultValues }),
	)
	return <kit.AutoForm form={form} />
}
```

Create a module-level form only when shared ownership and lifetime are
intentional. A new `defaultValues` object does not reset an existing form.

## FormRuntimeOptions

```text
type FormRuntimeOptions<Schema, Context = unknown> = {
	context?: Context
	disabled?: boolean
	readOnly?: boolean
	validation?: Partial<ValidationOptions>
	beforeUpdate?: CreateFormOptions["beforeUpdate"]
	afterUpdate?: CreateFormOptions["afterUpdate"]
	onSubmit?: SubmitHandler<Schema, Context>
}
```

Runtime options exclude `defaultValues` and `middleware`. A mounted binding
temporarily owns these values. The base options become active again after
unmount.

## kit.useForm

```text
kit.useForm(form, runtimeOptions: FormRuntimeOptions) => same FormInstance
```

This hook binds an existing form. It never creates a form. One instance can
have only one active `kit.useForm`, `kit.AutoForm`, or `ActionForm` binding.
The hook rejects a form from any other kit snapshot.

## Form and AutoForm

```text
<kit.Form form={form}>...</kit.Form>
<kit.AutoForm form={form}>...</kit.AutoForm>
```

`kit.Form` renders native form behavior and its children. `kit.AutoForm` also
renders the error summary and definition fields. Both accept native form props
and `FormRuntimeOptions`. Both reject a form from another exact kit.

Use `kit.Fields` inside `kit.Form` for manual composition. Use `kit.Submit` for
the kit-owned submit button.

## Hooks

| API | Result |
| --- | --- |
| `useFormContext()` | The nearest `FormInstance` from `FormProvider` or a form component |
| `useFormState(form, selector, options?)` | A selected snapshot value |
| `useValue(form, path, options?)` | The typed value at a path |
| `useField(form, path)` | Value, issues, metadata, and field commands |
| `useArrayField(form, path)` | Stable rows and typed array commands |

`FormProvider` and `useFormContext` remain public for headless composition.
Subscribe to the smallest state slice that a component needs.

## FormInstance

The instance is the primary command API:

```text
form.getSnapshot()
form.getValues()
form.getValue(path)
form.setValue(path, value)
form.setValues(partialValues)
form.unsetValue(path)
form.append(path, value?)
form.insert(path, index, value?)
form.remove(path, index)
form.move(path, from, to)
form.batch(callback)
form.reset(values?)
form.touch(path)
form.blur(path)
form.setErrors(issues)
form.clearErrors(path?)
form.validate()
form.validate(path)
form.validatePaths(paths)
form.focus(path)
form.focusFirstError(paths?)
form.replaceContext(context)
form.replaceOptions(options)
form.subscribe(selector, listener, options?)
form.submit()
```

Mutation commands return `void`. `validate()` returns a schema validation
result. Path validation returns overlapping issues. `focusFirstError` returns
whether focus moved. `reset(values)` installs a new clean document. `reset()`
restores the current clean baseline.

### Classic submission

`onSubmit` can return `void` or `Promise<void>`. The form keeps
`isSubmitting` true until the promise settles, and concurrent submissions use
the same in-flight promise. A rejected promise is not converted into a form
issue. Form, Please does not convert a rejected promise into a form issue.
Catch expected request failures and call `form.setErrors(...)` when the
user needs feedback. Call `form.reset(...)` after a save when the saved values
must become the clean baseline. `form.submit()` uses the same lifecycle as a
native classic submit.

## Commands

`FormCommand<Input, Context>` is the union accepted by middleware
`api.dispatch`:

```text
type FormCommand<Input, Context> =
	| { type: "value/set"; path: FieldPath<Input>; value: unknown }
	| { type: "values/set"; values: FormDeepPartial<Input> }
	| { type: "value/unset"; path: OptionalFieldPath<Input> }
	| { type: "array/append"; path: ArrayFieldPath<Input>; value?: unknown }
	| { type: "array/insert"; path: ArrayFieldPath<Input>; index: number; value?: unknown }
	| { type: "array/remove"; path: ArrayFieldPath<Input>; index: number }
	| { type: "array/move"; path: ArrayFieldPath<Input>; from: number; to: number }
	| { type: "form/reset"; values?: Input }
	| { type: "field/touch" | "field/blur"; path: FieldPath<Input> }
	| { type: "validation/run"; path?: FieldPath<Input> }
	| { type: "validation/runPaths"; paths: readonly FieldPath<Input>[] }
	| { type: "issues/set"; issues: readonly ImperativeFormIssue[] }
	| { type: "issues/clear"; path?: PathInput }
	| { type: "runtime/replaceContext"; context: Context }
	| { type: "runtime/replaceOptions"; options: FormStoreRuntimeOptions }
```

Nested dispatch runs after the current transaction completes. It does not
interrupt the current middleware stack.

## Transactions

```text
type FormTransaction<Input, Context> =
	| DocumentTransaction<Input>
	| RestoreTransaction<Input>
	| RuntimeTransaction<Context, Input>

type FormDispatchResult<Input, Context> =
	| { status: "committed"; event: FormEvent<Input, Context> }
	| { status: "cancelled" }
```

`DocumentTransaction` has `type: "document/committed"`, a source, grouping,
value changes, row-identity changes, and baseline disposition.
`RestoreTransaction` has `type: "document/restored"`, a complete document,
an origin, and history policy. Runtime transactions describe context,
validation, submission, touch, blur, issue, and reset transitions.

Transactions are immutable. A middleware handler can forward one unchanged,
forward a replacement, or cancel it.

## Events

`FormEvent<Input, Context>` is the committed event union:

- `document/committed` and `document/restored`;
- `runtime/replaced` and `runtime/reset`;
- `validation/started`, `validation/resolved`, and `validation/failed`;
- `submission/started` and `submission/finished`;
- `field/touched` and `field/blurred`;
- `issues/changed`.

Each event has a monotonic `sequence`. Document events are replayable.
Runtime events are not stored in history or persistence.

## Middleware

```text
type FormMiddleware<Input, Context> =
	(api: {
		getSnapshot(): FormSnapshot<Input, Context>
		dispatch(command: FormCommand<Input, Context>): void
	}) =>
	(next: FormTransactionDispatch<Input, Context>) =>
	(transaction: FormTransaction<Input, Context>) => FormDispatchResult<Input, Context>
```

Middleware is synchronous. See [Production recipes](/advanced) for ordering,
cancellation, replacement, restore, nested dispatch, and error rules.

## History

```text
import { createHistoryMiddleware, replayJournal } from "form-please/history"

createHistoryMiddleware({ limit?: number, groupWindow?: number }) => HistoryFeature
historyFeature.handle(form) => HistoryHandle
```

`limit` is an unlimited group count by default. `groupWindow` is `500`
milliseconds by default. Consecutive control commits to one path can share a
group. A batch is one group. Forwarded blur closes the active group.

```text
history.getSnapshot() // { canUndo, canRedo, index, length }
history.subscribe(listener) => unsubscribe
history.undo() => HistoryOperationResult
history.redo() => HistoryOperationResult
history.seek(index) => HistoryOperationResult
history.clear()
history.export() => FormJournal
await history.import(unknown) => HistoryOperationResult
replayJournal(journal, cursor) => FormDocument
```

An operation result is `"applied"`, `"unavailable"`, `"cancelled"`, or
`"transformed"`. Import validates untrusted journal structure asynchronously.
Replay is pure and has no form effects. Live navigation submits one restore
through middleware. History restores values and row identity, but not the
dirty baseline, touched state, issues, context, validation, or submission.

See [History and journals](/guides/history) for complete examples.

## Persistence

```text
createPersistenceMiddleware({
	adapter,
	key,
	version,
	codecs?,
	migrate?,
	saveDelay?,
	onError?,
	history?,
}) => PersistenceFeature

persistenceFeature.handle(form) => PersistenceHandle
```

`key` must be non-empty. `version` must be a non-negative integer.
`saveDelay` defaults to `500` milliseconds. Supply the same `HistoryFeature`
in `history` and in the form middleware list to persist the journal.

```text
await persistence.restore() => PersistenceRestoreResult
persistence.start()
await persistence.flush()
await persistence.clear()
persistence.getSnapshot() => PersistenceSnapshot
persistence.subscribe(listener) => unsubscribe
```

The phase is `"idle"`, `"restoring"`, `"active"`, or `"conflict"`. Save state
is `"idle"`, `"scheduled"`, `"saving"`, or `"failed"` with an error.
Restore returns `"applied"`, `"empty"`, `"cancelled"`, `"transformed"`,
`"unavailable"`, or `"conflict"`.

Construction is idle. Call `restore()` before local edits. A successful or
empty restore activates saving. Call `start()` when the application skips or
recovers from restore. A local edit during asynchronous restore produces a
conflict and remains authoritative.

### Adapters

```text
type FormPersistenceAdapter = {
	load(key: string): Promise<JsonValue | undefined>
	save(key: string, value: JsonValue): Promise<void>
	remove(key: string): Promise<void>
}

createLocalStorageAdapter(() => window.localStorage)
```

The local storage adapter reads storage only when an operation runs, so its
module is safe to import during SSR. Storage failures do not roll back form
commits. They reject the operation, set failed save state when applicable, and
call `onError`.

### Codecs and migration

```text
type PersistenceCodec<Value> = {
	tag: string
	canEncode(value: unknown): value is Value
	encode(value: Value): JsonValue | Promise<JsonValue>
	decode(value: JsonValue): Value | Promise<Value>
}

createDateCodec(tag = "date")
createFileCodec({ tag = "file", maxSize = 10 * 1024 * 1024 })

type PersistenceMigration =
	(payload: JsonValue, fromVersion: number, toVersion: number) =>
		JsonValue | Promise<JsonValue>
```

Codec tags must be non-empty and unique. `createFileCodec` is opt-in and
requires the browser `File` API. Migration receives decoded JSON before
document or journal validation. It must return JSON. The current schema then
validates hydrated values before restore.

See [Persistence](/guides/persistence) for local storage, nuqs, and TanStack
Query transports.

## Redux DevTools

```text
createDevToolsMiddleware(options?: CreateDevToolsOptions) => DevToolsFeature
devToolsFeature.handle(form) => DevToolsHandle
devTools.disconnect()
```

Supported connection options are `name`, `latency`, `maxAge`, `trace`,
`traceLimit`, `serialize`, `actionSanitizer`, `stateSanitizer`,
`actionsAllowlist`, `actionsDenylist`, `predicate`, and `autoPause`.
`onError` receives integration failures. `maxAge` defaults to `50`.

The integration sends committed events and a diagnostic projection of values
and logical row identity. It supports `JUMP_TO_STATE`, `JUMP_TO_ACTION`,
`RESET`, and `ROLLBACK`. It rejects arbitrary dispatch, skip, reorder, import,
lock, persisted monitor state, and generated tests. Navigation uses only an
opaque revision token from the bounded local table. Sanitized or serialized
monitor state is never trusted as form input.

`disconnect()` is idempotent and affects only that form. The feature is inert
during SSR or when the extension is absent. See [Redux DevTools](/guides/devtools).

## defineControl

`defineControl` connects one product control to typed value, option, focus,
accessibility, and `FormData` contracts. Use `mode: "native"`, `"hidden"`, or
`"none"` to declare submission behavior. Native option types include
`NativeTextOptions`, `NativeSelectOptions`, and `NativeFileOptions`.

## createDefaultSlots

```text
createDefaultSlots({ i18n? }) => FormKitSlots
```

The default slots provide semantic markup and English array action labels.
They do not provide a visual theme.

## React 19

```text
import { ActionForm, ActionSubmit } from "form-please/react19"

<ActionForm form={form} action={action} result={result}>
	<ActionSubmit>Save</ActionSubmit>
</ActionForm>
```

`ActionForm` gets its definition, controls, slots, and defaults from `form`.
It does not accept `kit`, `definition`, or `defaultValues`. It bypasses classic
client submission validation and reconciles serializable `FormResult` values.

## parseFormData

```ts twoslash
import { parseFormData } from "form-please/server"
import { z } from "zod"

const schema = z.object({ name: z.string().min(1) })
const formData = new FormData()
formData.set("name", "Ada")

const result = await parseFormData(formData, schema)

if (result.success) {
	result.value.name
} else {
	result.reply()
}
```

The parser normalizes bounded untrusted `FormData` and runs Standard Schema.
Defaults are `maxEntries: 1_000`, `maxPathLength: 1_024`, `maxDepth: 32`, and
`maxArrayIndex: 10_000`. Apply request and file limits before this function.

## React-free core

```text
import { createFormStore } from "form-please/core"

createFormStore({ definition, defaultValues, context?, ...runtimeOptions })
```

Use this constructor for React-free state. It exposes the imperative store,
selectors, validation, `resolveUi`, resource helpers such as `fromResource`
and `matchResource`, the `ResourceState` type, and path helpers such as
`FieldPath` and `ArrayFieldPath`. These resolver functions stay React-free.
The public core constructor does not configure the React middleware chain or
first-party optional feature handles.
