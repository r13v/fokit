# Get started

Build a schema-validated form and receive typed output when the user submits it.
At the end, you will have a working profile form, a visible validation error,
and a clear next step.

## Before you start

You need:

- an existing React 18 or React 19 application;
- TypeScript;
- a schema library that implements Standard Schema.

This guide uses Zod. Form, Please does not require Zod or a Zod adapter.

## Installation

Install `form-please` and the schema library used in this guide:

```sh
npm install form-please zod
```

Form, Please declares React and React DOM as peer dependencies. Both use the range
`^18.0.0 || ^19.0.0`.

## Verify the result

Complete these checks:

1. Submit the prefilled form. The page shows the validated profile as JSON.
2. Select Company. The company name field appears.
3. Select Personal. The company name field disappears.
4. Replace the contact email with an invalid value.
5. Submit the form again. Form, Please shows the schema issue and focuses the email
   control.
6. Restore a valid email and submit. The handler receives
   `FormOutput<typeof profileSchema>`.

The shipped controls and slots are accessible semantic HTML, not a visual
theme. For optional structural spacing, import `form-please/layout.css` in your
application entry point. You can also style the exposed markup yourself.

## What just happened

### Schema owns validity

`profileSchema` contains all validation rules. Form, Please stores editable
`FormInput<typeof profileSchema>` values. After successful validation, Form, Please
passes `FormOutput<typeof profileSchema>` to `onSubmit`.

This separation lets schema transforms change the output type without replacing
the editable values.

### `onSubmit` can wait for async work

`onSubmit` can return `void` or `Promise<void>`. Use an async callback when it
must wait for a client request. For example, use
`onSubmit={async ({ value }) => { await saveProfile(value) }}`.

Form, Please keeps `isSubmitting` set to `true` while it waits. `kit.Submit` stays
disabled until the promise settles. Concurrent submit attempts use the same
in-flight promise and do not call `onSubmit` again.

Form, Please does not reset the form after success. Call `form.reset(...)` when saved
values must become the new baseline. A rejected promise is not a validation
issue. Handle expected request failures in `onSubmit`, and call
`form.setErrors(...)` when the form must show an issue.

### UI definition owns structure

`profileDefinition` specifies paths, controls, labels, and presentation options.
Form, Please does not infer the UI from Zod or other schema metadata. A schema change
therefore cannot silently change the product UI.

### The kit owns rendering

`createFormKit({ controls: nativeControls })` maps control names to the shipped
native renderers. It also supplies accessible structural slots.

`kit.AutoForm` creates the form instance and renders the definition. You can
later render the same definition with `kit.Form`, `kit.Fields`, and granular
hooks.

## What you get out of the box

- Schema-owned synchronous or asynchronous validation.
- Typed editable values and validated submit output.
- Accessible labels, descriptions, issue relationships, and first-error focus.
- Stable array commands and explicit hidden-value behavior.
- Granular subscriptions for manual rendering.
- Native names and `FormData` coordination for classic submission.
- An isolated `form-please/react19` entry for React 19 Actions.

## Make it yours

`nativeControls` and the default slots are a working baseline. They are not a
design system. Use `defineControl` to replace controls. Override structural
slots when their markup must change. Use `createDefaultSlots({ i18n })` to
change the default action labels.

Form, Please keeps those choices separate from the reusable form definition. Product
controls can change without rewriting validation, conditions, arrays, or submit
behavior.

## Fix common setup problems

### The form has no visual layout

Import `form-please/layout.css` for the optional responsive structure, or add your own
styles. Form, Please does not ship a visual theme.

### A required field accepts an empty value

Add the rule to the schema. The UI option `required: true` marks the control as
required in presentation, native state, and ARIA. It does not add a validation
rule.

### TypeScript rejects `defaultValues`

Provide a value for every field in `FormInput<typeof profileSchema>`. Use
`undefined` only when the input type permits it.

### `onSubmit` does not run

Correct all visible schema issues and submit again. Form, Please calls `onSubmit` only
after successful validation.
