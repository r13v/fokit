# Controls and design systems

A Fokit control is the adapter between one typed value and the input component
your product already owns. Wrap a component once, then reuse it across every
generated and manually composed form.

## Choose the smallest integration

| Need | Start with |
| --- | --- |
| Working semantic HTML | `nativeControls` |
| Product input components | Add controls with `defineControl` |
| Different field or array markup | Override structural slots |
| Fully bespoke form sections | Compose `kit.Form`, `kit.Fields`, and hooks |

Controls own values and native serialization. Slots own labels, descriptions,
errors, sections, and array structure.

## Wrap a product input

The adapter forwards Fokit's value, events, native name, ref, and accessible
relationships into the product component:

```tsx twoslash
// @jsx: react-jsx
import {
	type ControlProps,
	createFormKit,
	defineControl,
	nativeControls,
} from "fokit"
import type { ComponentPropsWithRef } from "react"

type TextOptions = {
	readonly placeholder?: string
	readonly autoComplete?: string
}

function ProductTextInput(props: ComponentPropsWithRef<"input">) {
	return <input {...props} className="product-input" />
}

const productText = defineControl<string | undefined, TextOptions>({
	component({
		value,
		setValue,
		blur,
		input,
		meta,
		options,
		disabled,
		readOnly,
		required,
	}: ControlProps<string | undefined, TextOptions>) {
		return (
			<ProductTextInput
				aria-describedby={input["aria-describedby"]}
				aria-invalid={meta.invalid || undefined}
				autoComplete={options.autoComplete}
				disabled={disabled}
				id={input.id}
				name={input.name}
				onBlur={blur}
				onChange={(event) => setValue(event.currentTarget.value)}
				placeholder={options.placeholder}
				readOnly={readOnly}
				ref={input.ref}
				required={required}
				value={value ?? ""}
			/>
		)
	},
	formData: {
		mode: "native",
		serialize(value, { name }) {
			return value === undefined ? [] : [{ name, value }]
		},
	},
})

const kit = createFormKit({
	controls: {
		...nativeControls,
		productText,
	},
})
```

The registry key becomes the definition discriminator:

```ts twoslash
import { createFormKit, defineControl, nativeControls } from "fokit"
import { z } from "zod"

const productText = defineControl<string | undefined>({
	component: () => null,
	formData: { mode: "native" },
})
const kit = createFormKit({
	controls: { ...nativeControls, productText },
})
const schema = z.object({ name: z.string().optional() })

// ---cut---
const definition = kit.defineForm(schema)({
	ui: [
		{
			kind: "field",
			path: "name",
			control: "productText",
			label: "Name",
		},
	],
})
```

TypeScript rejects a control whose value contract does not match the selected
schema path.

## Preserve the control contract

Every custom control should forward:

- `input.id`, `input.name`, `input.ref`, and
  `input["aria-describedby"]`;
- `blur` on native blur and `setValue` on accepted changes;
- `disabled`, `readOnly`, and `required`;
- `meta.invalid` or `meta.displayErrors` for invalid state.

Forward `disabled` to the native disabled state: the control is unavailable and
does not need to remain focusable. Text-like controls can use native `readOnly`.
Widgets without that attribute must remain enabled, named, and focusable while
preventing value mutation and exposing `aria-readonly`.

Read [Choose disabled or read-only](/guides/ui-definitions#choose-disabled-or-read-only)
for the product-level distinction between the two states.

## Choose a FormData mode

| Mode | Use it when | Serializer |
| --- | --- | --- |
| `"native"` | The visible element emits a usable native entry. | Optional, but needed to preserve hidden or disabled values. |
| `"hidden"` | The widget has no successful native control, such as a segmented picker. | Required. |
| `"none"` | The value is client-only. | Not used. |

An active `mode: "none"` value works with classic `onSubmit` but is
incompatible with `ActionForm`.

Serializers return explicit name/value entries or array markers. Browser
protocol still matters: visible unchecked checkboxes are absent, number and
date entries are strings, and a `File` cannot be represented by a hidden input.

## Native controls

`nativeControls` is a normal registry built with `defineControl`:

| Control | Store value | Options summary |
| --- | --- | --- |
| `text` | `string \| undefined` | `type`, `placeholder`, `autoComplete` |
| `textarea` | `string \| undefined` | `rows`, `placeholder`, `autoComplete` |
| `select` | `string` | explicit `options` |
| `checkbox` | `boolean` | native checked/unchecked behavior |
| `number` | `number \| undefined` | `min`, `max`, `step`, `placeholder` |
| `date` | `string \| undefined` | `min`, `max` |
| `file` | `File \| undefined` | single file and `accept` |

Start with these controls to prove the form model. Replace only the controls
that need product components. The [API reference](/api#nativecontrols) lists
every option with its exact type and default.

## Replace structural slots

Slots let the design system own wrappers and feedback without reimplementing
control state:

```tsx twoslash
// @jsx: react-jsx
import {
	createDefaultSlots,
	createFormKit,
	nativeControls,
	type FieldSlotProps,
} from "fokit"

function ProductField({
	rootProps,
	label,
	labelProps,
	description,
	descriptionProps,
	control,
	errors,
}: FieldSlotProps) {
	return (
		<div {...rootProps} className="product-field">
			{label === undefined ? null : <label {...labelProps}>{label}</label>}
			{description === undefined ? null : (
				<p {...descriptionProps}>{description}</p>
			)}
			{control}
			{errors}
		</div>
	)
}

const kit = createFormKit({
	controls: nativeControls,
	slots: {
		...createDefaultSlots({
			i18n: {
				arrayAdd: "Add contact",
				arrayRemove: ({ position }) => `Remove contact ${position}`,
			},
		}),
		Field: ProductField,
	},
})
```

The five slots are `Field`, `Section`, `Array`, `ArrayItem`, and
`ErrorMessage`. Keep forwarding their public props so labels, focus targets,
layout data, and errors remain connected.
