# Get started

Fokit works with React 18+, TypeScript 5+, and any schema library that
implements Standard Schema. The shortest path uses the shipped `nativeControls`
registry and the English default structural slots resolved by `createFormKit`.

## Installation

```sh
npm install fokit zod
npm install react react-dom
```

React is a peer dependency with the range `^18.0.0 || ^19.0.0`. The examples
use Zod because it implements Standard Schema, but the form APIs are not tied
to Zod.

Use the main `fokit` entry for React 18-compatible forms. Use `fokit/server` in
server code, `fokit/react19` only for React 19 Actions, and import
`fokit/layout.css` explicitly only when you want the optional structural CSS.

## Build your first form

Start with a schema, complete editable defaults, and a UI definition that
selects controls by name.

```tsx twoslash
// @jsx: react-jsx
import { createFormKit, nativeControls, type FormOutput } from "fokit"
import { z } from "zod"

const profileSchema = z.object({
	name: z.string().min(1, "Name is required"),
	email: z.string().email("Enter a valid email"),
	newsletter: z.boolean(),
})

const defaults = {
	name: "",
	email: "",
	newsletter: false,
}

const kit = createFormKit({
	controls: nativeControls,
})

const profileDefinition = kit.defineForm({
	schema: profileSchema,
	ui: [
		{ kind: "field", path: "name", control: "text", label: "Name" },
		{ kind: "field", path: "email", control: "text", label: "Email" },
		{ kind: "field", path: "newsletter", control: "checkbox", label: "News" },
	],
})

function saveProfile(value: FormOutput<typeof profileSchema>) {
	void value
}

// ---cut---
export function ProfileForm() {
	return (
		<kit.AutoForm
			definition={profileDefinition}
			defaultValues={defaults}
			onSubmit={({ value }) => saveProfile(value)}
		>
			<kit.Submit>Save profile</kit.Submit>
		</kit.AutoForm>
	)
}
```

## Create a kit with native controls

`createFormKit({ controls: nativeControls })` resolves all five slots once for
the kit: `Field`, `Section`, `Array`, `ArrayItem`, and `ErrorMessage`. The
defaults render semantic, accessible, unstyled HTML with English action labels.

```ts twoslash
import { createDefaultSlots, createFormKit, nativeControls } from "fokit"

const kit = createFormKit({
	controls: nativeControls,
	slots: {
		...createDefaultSlots({
			i18n: {
				arrayAdd: "Add contact",
				arrayRemove: ({ position }) => `Remove contact ${position}`,
			},
		}),
	},
})
```

Every i18n entry can be a string or a function. Missing entries fall back to
English. `arrayAdd` functions receive `{ label }`; `arrayRemove`,
`arrayMoveUp`, and `arrayMoveDown` functions receive zero-based `index` and
one-based `position`.

Controls remain explicit. Add product controls by composing the registry:

```ts twoslash
import { createFormKit, defineControl, nativeControls } from "fokit"

const money = defineControl<number>({
	component: () => null,
	formData: { mode: "none" },
})

const kit = createFormKit({
	controls: {
		...nativeControls,
		money,
	},
})
```

## Render a generated form

`kit.AutoForm` creates a `FormInstance`, renders the normalized definition, and
coordinates classic native submission. You can leave generated rendering at any
point and reuse the same instance with `kit.Form`, `kit.Fields`, `useForm`,
`useField`, `useValue`, or `useArrayField`.

Generated fields preserve native names, IDs, descriptions, labels, required
state, read-only state, disabled state, issue relationships, and focus targets.
The default slots pass those props through; custom slots must do the same.

## Validation follows the schema

Validation defaults to submit-first behavior. Configure `validation.mode`,
`revalidateMode`, and `asyncDebounceMs` on `useForm` or `kit.AutoForm` when a
form needs blur or change validation.

```ts twoslash
import { createFormKit, nativeControls } from "fokit"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })
const definition = kit.defineForm({
	schema,
	ui: [{ kind: "field", path: "name", control: "text", label: "Name" }],
})

// ---cut---
const options = {
	definition,
	defaultValues: { name: "" },
	validation: {
		mode: "blur",
		revalidateMode: "change",
		asyncDebounceMs: 150,
	},
} satisfies Parameters<typeof kit.AutoForm>[0]
```

The store contains editable `FormInput<Schema>`. A successful submission
returns validated `FormOutput<Schema>`, so schema transforms do not silently
replace the editable values.

## Submit with native form semantics

Classic submission captures the browser's `FormData`, validates the current
store snapshot, exposes schema issues, focuses the first issue target, prevents
duplicate submits, and calls `onSubmit` with typed output.

React 19 Actions use `ActionForm` and `ActionSubmit` from `fokit/react19`.
Those components keep the server Action on the native form and synchronize the
serializable `FormResult` returned by `parseFormData`.

## Native FormData caveats

`nativeControls` intentionally follow browser protocol details:

- `text`, `textarea`, and `date` use `string | undefined`; undefined renders as
  an empty control and hidden preservation omits the entry.
- `number` stores `number | undefined`, but visible native FormData contains a
  string.
- `date` stores the native `YYYY-MM-DD` string, not a JavaScript `Date`.
- `checkbox` stores `boolean`; a visible unchecked checkbox is absent from
  native FormData, while hidden preservation serializes the boolean value.
- `file` stores `File | undefined`; browsers do not allow a default `File` to
  hydrate an input, and hidden or disabled file values cannot be serialized.

Server code should treat FormData as untrusted input and let the schema coerce
browser protocol strings into domain values.
