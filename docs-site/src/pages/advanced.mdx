# Production recipes

Use these recipes after the first form works. Each recipe keeps one owner for
the form and one explicit boundary for side effects.

## Choose a focused guide

- [History and journals](/guides/history) covers undo, redo, seek, replay,

- [Persistence](/guides/persistence) covers hydration, migration, codecs, and
  storage adapters.

## Compose generated and bespoke UI

Create the form once. Use `FormProvider`, `useFormContext`, and granular hooks
when a component must be independent of the generated tree.

```text
import {
	FormProvider,
	createFormKit,
	nativeControls,
	useFormContext,
	useFormState,
} from "form-please"
import { useState } from "react"

const kit = createFormKit({ controls: nativeControls })

function DirtyStatus() {
	const form = useFormContext()
	const dirty = useFormState(form, (snapshot) => snapshot.isDirty)
	return <output>{dirty ? "Unsaved changes" : "Saved"}</output>
}

function Editor() {
	const [form] = useState(() =>
		kit.createForm(definition, { defaultValues }),
	)

	return (
		<kit.Form form={form}>
			<kit.Fields />
			<DirtyStatus />
			<kit.Submit>Save</kit.Submit>
		</kit.Form>
	)
}
```

Controls receive `labelProps`, descriptions, issues, and refs through their
control contract. Do not rebuild those accessibility relationships in the
parent form.

## Load an edit-form baseline

Wait for loaded data before you mount the component that creates the form.
This makes the loaded values the initial clean baseline.

```text
function ProfileScreen({ profile }) {
	if (profile === undefined) return <p>Loading…</p>
	return <ProfileEditor key={profile.id} profile={profile} />
}

function ProfileEditor({ profile }) {
	const [form] = useState(() =>
		kit.createForm(definition, { defaultValues: profile }),
	)
	return <kit.AutoForm form={form} />
}
```

After a successful save, call `form.reset(profile)` to install the saved
document as the new baseline. A prop identity change does not reset a form.

## Middleware protocol

Configure middleware only in `kit.createForm`:

```text
import type { FormMiddleware } from "form-please"

const audit: FormMiddleware<Input, Context> =
	(api) => (next) => (transaction) => {
		const before = api.getSnapshot()
		const result = next(transaction)
		const after = api.getSnapshot()
		record({ transaction, result, before, after })
		return result
	}
```

The declaration order is outer-to-inner. For `[audit, policy]`, `audit` sees
the transaction first and unwinds last.

### Forward synchronously

Call `next(transaction)` during the current handler call. Call it at most
once. Return its result unchanged. An async handler, a promise result, a second
`next` call, or a changed result throws a protocol error.

### Cancel or replace deliberately

Do not call `next` to cancel a transaction. The caller receives
`{ status: "cancelled" }`. To replace a transaction, create a new value and
pass it to `next`. Transactions are frozen, so do not mutate them.

Application middleware has this authority for document, runtime, validation,
submission, blur, and restore transactions. A replacement must still satisfy
core invariants.

### Dispatch nested commands

`api.dispatch(command)` adds a nested command to a FIFO queue. The coordinator
runs that command only after the current transaction and its publication
finish. This rule prevents a nested command from changing state while the
current middleware stack is unwinding.

### Understand errors and finalized delivery

An error before the core commit aborts the transaction. An error after a core
commit propagates to the caller, but it does not roll back the committed state.
The coordinator still publishes one coherent snapshot and delivers the
effective finalized event exactly once. History, persistence, DevTools, and
React 19 Action tracking use that guaranteed delivery point.

`api.getSnapshot()` reads the effective pending committed snapshot after
`next` commits, even before outer middleware returns.

### Treat repeated blur as an event

A forwarded `field/blurred` transaction commits every time, even when the
field is already touched and no issue exposure changes. History uses the event
to close an active control-edit group. Cancellation prevents the blur event
and its automatic validation.

## Restore boundary

Undo, redo, seek, journal import, persistence hydration, replay, and DevTools
navigation submit one `document/restored` transaction through middleware.

A restore bypasses:

- `beforeUpdate` and `afterUpdate`;
- `valuePolicy` and `itemDefault`;
- schema transforms and automatic validation;
- application mutation callbacks.

A committed restore installs values and row identity atomically. It does not
restore the dirty baseline, touched state, issues, validation, submission,
context, runtime options, focus targets, or subscriptions. It invalidates
captured validation and server results and publishes once.

Application middleware can cancel or replace a restore. History, persistence,
and DevTools report `"cancelled"` or `"transformed"` when exact restoration
does not occur.

## Preserve application-owned immutable values

Form, Please clones and freezes plain structures. It also detaches `Date` and
`RegExp` values at public boundaries. `File` and other opaque leaves remain
application-owned identities.

Treat each opaque leaf as immutable after dispatch. If application code
changes an object in place, snapshots, journals, and middleware cannot detect
or isolate that mutation. Replace the leaf through a form command instead.

## Treat FormData as untrusted

Parse server input through the server entry:

```text
import { parseFormData } from "form-please/server"

const result = await parseFormData(formData, schema)
```

Do not use `Object.fromEntries` for nested forms. Apply request, multipart,
file-count, and file-size limits before `parseFormData`. The parser protects
the value structure, not the transport body.

Return a serializable `FormResult` from a React 19 Action. Use field paths for
field issues and omit the path for a form issue.

## Preserve the accessibility contract

Custom controls must attach the supplied name, ID, ref, `labelProps`, and ARIA
relationships to the interactive element. Custom slots must keep semantic
grouping and issue output. Use `form.focusFirstError()` in staged workflows
instead of searching the DOM yourself.

## Test the public experience

Test through package imports and visible behavior:

1. Create the form through `kit.createForm`.
2. Render `kit.AutoForm`, `kit.Form`, or `ActionForm` with that form.
3. Interact through labels and roles.
4. Assert visible issues, focus, values, and submission results.
5. For optional features, assert handle state and the committed document.

Do not test private reducer objects through deep imports. Use the public
`form-please/core` entry only when the product intentionally uses the
React-free `createFormStore` API.
