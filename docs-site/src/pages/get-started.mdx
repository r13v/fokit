# Get started

Build a working, schema-validated form and receive typed output on submit. The
path is deliberately explicit: the schema owns validity, the UI definition owns
structure, and the kit owns rendering.

Fokit works with React 18+, TypeScript 5+, and any schema library that
implements Standard Schema. This guide uses Zod in an existing React
application.

## Installation

```sh
npm install fokit zod
```

React and React DOM are peer dependencies with the range
`^18.0.0 || ^19.0.0`. Zod is only the example schema library; Fokit does not
require it or an adapter.

## Build your first form

Put this component in your application and render `<ProfileForm />`. It starts
with the same profile shown on the overview page, validates on submit, and shows
the schema-validated output.

```tsx twoslash
// @jsx: react-jsx
import {
	createFormKit,
	type FormInput,
	type FormOutput,
	nativeControls,
} from "fokit"
import { useState } from "react"
import { z } from "zod"

const profileSchema = z.object({
	name: z.string().min(1, "Name is required"),
	email: z.string().email("Enter a valid email"),
	newsletter: z.boolean(),
})

const defaultValues = {
	name: "Ada Lovelace",
	email: "ada@example.com",
	newsletter: true,
} satisfies FormInput<typeof profileSchema>

const kit = createFormKit({
	controls: nativeControls,
})

const profileDefinition = kit.defineForm(profileSchema)({
	ui: [
		{
			kind: "field",
			path: "name",
			control: "text",
			label: "Name",
			required: true,
			options: { autoComplete: "name" },
		},
		{
			kind: "field",
			path: "email",
			control: "text",
			label: "Email",
			required: true,
			options: { type: "email", autoComplete: "email" },
		},
		{
			kind: "field",
			path: "newsletter",
			control: "checkbox",
			label: "Send me product news",
		},
	],
})

export function ProfileForm() {
	const [saved, setSaved] = useState<FormOutput<typeof profileSchema>>()

	return (
		<>
			<kit.AutoForm
				definition={profileDefinition}
				defaultValues={defaultValues}
				onSubmit={({ value }) => setSaved(value)}
			>
				<kit.Submit>Save profile</kit.Submit>
			</kit.AutoForm>
			<pre aria-live="polite">
				{saved === undefined
					? "Submit the form to see typed output."
					: JSON.stringify(saved, null, 2)}
			</pre>
		</>
	)
}
```

Submit once, then replace the email with an invalid value and submit again.
Fokit exposes the schema issue beside the field and focuses the first invalid
control. Restore a valid email and the handler receives
`FormOutput<typeof profileSchema>`.

The shipped controls and slots are accessible semantic HTML, not a visual
theme. Import `fokit/layout.css` in your application entry point when you want
optional structural spacing, or style the exposed markup yourself.

## What just happened

### Schema owns validity

`profileSchema` is the only validation language in the example. Fokit stores
editable `FormInput<typeof profileSchema>` and passes validated
`FormOutput<typeof profileSchema>` to `onSubmit`, so schema transforms can
produce a different output type without replacing editable values.

### UI definition owns structure

`profileDefinition` explicitly chooses paths, controls, labels, and presentation
options. Fokit does not infer UI from Zod or other schema metadata. That keeps a
domain-schema change from silently changing the product experience.

### The kit owns rendering

`createFormKit({ controls: nativeControls })` maps control names to shipped
native renderers and fills in accessible default structural slots.
`kit.AutoForm` creates the form instance and renders the definition. The same
definition can later be composed manually with `kit.Form`, `kit.Fields`, and
granular hooks.

## What you get out of the box

- Schema-owned synchronous or asynchronous validation.
- Typed editable input and validated submit output.
- Accessible labels, descriptions, issue relationships, and first-error focus.
- Stable array commands and explicit hidden-value behavior.
- Granular subscriptions when generated rendering is not enough.
- Native names and `FormData` coordination for classic submission.
- An isolated `fokit/react19` entry for React 19 Actions.

## Make it yours

`nativeControls` and the default slots are a working baseline, not a design
system. Replace controls with `defineControl`, override one or more structural
slots, or call `createDefaultSlots({ i18n })` when the default action labels need
to change.

Fokit keeps those choices separate from the reusable form definition. Product
controls can change without rewriting validation, conditions, arrays, or submit
behavior.
