# Transaction hooks

Transaction hooks apply one rule to every value update. Use `beforeUpdate` to
change a proposal before Form, Please commits it. Use `afterUpdate` to observe values
after Form, Please commits them.

## Choose the correct mechanism

Use hooks only when the rule applies to the update lifecycle.

| Goal | Mechanism |
| --- | --- |
| Validate input on the client and server | Schema validation |
| Remove an optional value when its field becomes hidden | `valuePolicy: "unset"` |
| Prevent interaction with a field | `disabled` or `readOnly` |
| Change or cancel one complete value update | `beforeUpdate` |
| Start an effect after a value update | `afterUpdate` |

Cancellation is not validation. A canceled update does not create a form
issue. Put validity rules in the schema so the server uses the same rules.

## Follow one transaction

Each value command enters the same transaction pipeline:

`command → proposal → beforeUpdate → commit → afterUpdate`

Form, Please completes these actions in order:

1. Form, Please converts the command into `set` and `unset` changes.
2. Form, Please applies required `valuePolicy` changes to the proposal.
3. Form, Please calls `beforeUpdate` once with the complete proposal.
4. Form, Please commits the effective changes as one atomic update.
5. Form, Please notifies subscribers and calls `afterUpdate` once.

A batch creates one transaction. Nested batches join the outer batch.

### Select a beforeUpdate result

| Return value | Result |
| --- | --- |
| `undefined` | Commit the proposal without a replacement. |
| `false` | Cancel the complete transaction. Do not call `afterUpdate`. |
| `ValueChange[]` | Replace the complete proposal with this change list. |

A returned array does not append changes to the proposal. Use
`extendValueChanges` when you must keep the original changes.

Replacement changes use typed schema paths. A `set` value must match its path.
An `unset` change can target only an optional path.

### Read the proposal

The `BeforeUpdateEvent` fields have these meanings:

| Field | Meaning |
| --- | --- |
| `currentValues` | Values before the proposal. |
| `nextValues` | Values after the complete proposal. |
| `changes` | Proposed `set` and `unset` changes. |
| `source` | API category that started the transaction. |
| `context` | Current read-only form context. |

The snapshots and change list are read-only. Do not call a value command from
`beforeUpdate`. Return replacement changes instead.

The `UpdateEvent` contains `previousValues`, committed `values`, effective
`changes`, `source`, and `context`.

Form, Please does not roll back a commit when `afterUpdate` throws. Form, Please also does not
wait for asynchronous work that the hook starts. The application must manage
debouncing, request cancellation, and stale responses.

Do not use `afterUpdate` to keep dependent values synchronized. A value command
from `afterUpdate` starts a new transaction. It can also create an update loop.
Use `beforeUpdate` when dependent values must commit together.

## Identify the update source

Each event has one `source` value:

| Source | Initiating operation |
| --- | --- |
| `"control"` | A control changed a value. |
| `"imperative"` | A value command or batch changed values. |
| `"array"` | An array command changed values or row order. |
| `"reset"` | A reset changed values. |
| `"valuePolicy"` | UI resolution required a value change. |

The change list always contains `set` and `unset` changes. An array command does
not add a separate array change type.

## Know when hooks do not run

Form, Please does not call either transaction hook for these operations:

- initial `defaultValues`;
- a value command that has no effective change;
- validation, errors, focus, touch, or other metadata changes;
- a context replacement;
- a reset that changes only reset metadata.

Form, Please calls `beforeUpdate` for a transaction that the hook cancels. Form, Please does
not call `afterUpdate` for that transaction.

If `beforeUpdate` throws, Form, Please aborts the transaction and propagates the
error. If `afterUpdate` throws, Form, Please keeps the committed values and propagates the
error.
