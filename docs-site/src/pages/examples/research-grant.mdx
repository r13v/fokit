# Research grant application

This application changes shape according to who applies, how a collective is
represented, which settlement route it uses, and its reporting status. The
long-lived project fields remain stable while branch-specific identity and
payment values are removed in the same Fokit transaction that changes their
discriminator.

## Try the complete flow

Switch **Applying as** to **A collective**, choose a representation path, and
use the fake registry search. Change the disbursement route to see mutually
exclusive account fields clean up. Submission first builds a review preview and
then sends the accepted application through a second mutation.

## What this form stresses

- Deep paths across identity, project, settlement, and reporting objects.
- An optional enum rendered through `select.emptyOption` without a domain
  sentinel value.
- Resolver-driven sections and `valuePolicy` cleanup for hidden optional fields.
- A `beforeUpdate` hook that atomically clears dependent branches.
- A render node that reads the live Fokit snapshot for a review card.
- TanStack Query inside a render node for registry search.
- Two sequential mutations with server errors installed on the form instance.
- A schema transform that creates a typed review key for submission.

The registry data and both mutations are deterministic browser-side requests.
Replace `fakeRequest` at the network boundary; the schema, definition, and
transaction rules do not need to change.
