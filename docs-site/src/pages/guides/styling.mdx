# Styling

Form, Please ships accessible semantic markup and optional responsive structure. Your
application owns the visual language: typography, color, borders, focus,
density, and component polish.

The shortest useful path is:

1. import structural layout;
2. give the form a product class;
3. style native controls and public state attributes under that class.

## Import responsive structure

Import the stylesheet once when you want the Form, Please grid and spacing behavior:

```ts twoslash
// @filename: layout-css.d.ts
declare module "form-please/layout.css" {}
// @filename: example.ts

// ---cut---
import "form-please/layout.css"
```

The JavaScript entry never imports CSS. Custom kits and server bundles stay in
control of their own styling.

The stylesheet provides:

- stacked form, field, section, and array structure;
- one to four section columns through container queries;
- `span` support, including `span: "full"`;
- independent nested layout containers;
- four spacing custom properties.

It does not set colors, fonts, borders, shadows, or control appearance.

## Add a product class

Scope product styling through the native form class:

```tsx twoslash
// @jsx: react-jsx
import { createFormKit, nativeControls } from "form-please"
import { z } from "zod"

const schema = z.object({ name: z.string() })
const kit = createFormKit({ controls: nativeControls })
const definition = kit.defineForm(schema, {
	ui: [
		{
			kind: "field",
			path: "name",
			control: "text",
			label: "Name",
		},
	],
})

// ---cut---
function ProfileForm() {
	const form = kit.useCreateForm(definition, {
		defaultValues: { name: "" },
	})
	return (
		<kit.AutoForm className="profile-form" form={form}>
			<kit.Submit>Save profile</kit.Submit>
		</kit.AutoForm>
	)
}
```

## Copy a visual baseline

This example styles the shipped native controls while preserving browser
semantics and visible focus:

```css
.profile-form {
	--fp-column-gap: 1rem;
	--fp-row-gap: 0.9rem;
	--fp-stack-gap: 0.75rem;
	--fp-array-item-gap: 1rem;

	color: #17211b;
	max-width: 48rem;
}

.profile-form :where(label) {
	font-weight: 650;
}

.profile-form :where(
	input:not([type="checkbox"], [type="file"]),
	textarea,
	select
) {
	background: #ffffff;
	border: 1px solid #748079;
	border-radius: 0.5rem;
	color: inherit;
	font: inherit;
	min-height: 2.75rem;
	padding: 0.65rem 0.75rem;
	width: 100%;
}

.profile-form :where(input, textarea, select, button):focus-visible {
	outline: 3px solid #b7e4c7;
	outline-offset: 2px;
}

.profile-form
	[data-fp-node="field"][data-invalid]
	:where(input, textarea, select) {
	border-color: #b42318;
}

.profile-form [data-fp-node="error-message"] {
	color: #b42318;
	margin: 0;
}

.profile-form :where(button) {
	border: 1px solid #245c3b;
	border-radius: 0.5rem;
	cursor: pointer;
	font: inherit;
	padding: 0.65rem 0.9rem;
}

.profile-form :where(button[type="submit"]) {
	background: #245c3b;
	color: #ffffff;
}

.profile-form :where([data-disabled]) {
	opacity: 0.65;
}
```

Treat the colors as placeholders for product tokens. Keep the behavior:
controls need a visible boundary, focus must remain distinct, and error styling
must not rely on color alone—the connected message provides the explanation.

## Style public states

Forms and structural nodes expose stable attributes:

- `data-fp-node="form" | "field" | "section" | "array" | "array-item"`;
- `data-fp-layout="grid"` and `data-fp-columns`;
- `data-dirty`, `data-touched`, and `data-invalid`;
- `data-disabled`, `data-readonly`, and `data-validating`.

Boolean attributes are omitted when false. Use them for state styling, not to
infer private DOM order.

Only these structural variables are public:

```css
.profile-form {
	--fp-column-gap: 1rem;
	--fp-row-gap: 0.75rem;
	--fp-stack-gap: 0.75rem;
	--fp-array-item-gap: 0.75rem;
}
```

## Replace markup when selectors are not enough

Default slots are a semantic fallback, not a required DOM shape. If a design
system needs a field wrapper, error component, or array toolbar with different
markup, replace that slot and forward its public props.

Do not depend on private sibling order. Product classes, slot props, and public
data attributes are the stable styling contract.
